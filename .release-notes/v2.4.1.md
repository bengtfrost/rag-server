**Dependency hygiene, observability, and a silent result-quality fix.**

### Correctness — `hybrid_search` was returning the worst `k`

Both retrieval channels put their *best* result at the **minimum** of the raw score stream (`sqlite-vec` distances, FTS5 `bm25()`). The old normalizer mapped best → `0.0` but then sorted **descending** before `truncate(k)`, so `--hybrid` was returning the *worst* candidates. Fixed by normalizing to *similarity* (1 = best, missing channel = 0) and sorting descending by weighted similarity, then converting back to distance at the return boundary so `search()` and `hybrid_search()` share one "lower is better" contract.

If hybrid mode ever felt worse than plain vector search, this was why. Re-run important hybrid queries after upgrading.

### Observability — `tracing` was a no-op

`tracing-subscriber` was declared in `Cargo.toml` but `.init()` was never called, so every `tracing::debug!` / `warn!` in `cache.rs`, `chunker.rs`, `embedder.rs`, `expander.rs` and `query.rs` was silently discarded. Now initialized in `main.rs`, writing to **stderr** (stdout is the JSON-RPC wire). Default filter `rag_server_mcp=debug,info`; override with `RUST_LOG`. `eprintln!` calls replaced with `tracing` macros; malformed JSON-RPC lines and tool panics are logged at `warn`.

### Performance — `chunker.rs` hot paths

- Sentence-splitting regex was compiled **once per call to `chunk_text`** — i.e. once per file during `ingest_directory`. Now compiled once per process (`LazyLock`).
- BGE tokenizer was parsed **once per file**. Now parsed once per process (`OnceLock`).

Combined, these dominate the prepare phase of bulk ingestion.

### Configuration hardening (`config.rs`)

- Invalid env values now emit a `warn!` instead of silently falling back (`RAG_CHUNK_SIZE=abc` used to become `1024` with no signal).
- Hard-fails on `RAG_CHUNK_SIZE=0` / `RAG_BATCH_SIZE=0` / `RAG_TIMEOUT_SECS=0` — each would previously panic at runtime.
- Warns on `chunk_overlap >= chunk_size`.
- Config-dir creation is best-effort, so the server starts on a read-only FS when `RAG_DB_PATH` and `RAG_TOKENIZER_PATH` are both set.

### New environment variables

| Variable | Default | Notes |
|---|---|---|
| `RAG_TIMEOUT_SECS` | `14400` | Was hardcoded. Now tunable — set to `30` to fail fast on a stuck backend. |
| `RAG_EXPAND_URL` | `http://localhost:4000/v1/chat/completions` | Was hardcoded in `expander.rs`. |
| `RAG_EXPAND_AUTH_TOKEN` | _(unset → no header)_ | Replaces the hardcoded `Bearer sk-unused` header. |
| `RUST_LOG` | `rag_server_mcp=debug,info` | Now actually works (see above). |

### Path resolution

`./tokenizer.json` and `./extensions/vec0.{so,dylib,dll}` are now probed in the CWD before falling back to `~/.config/rag-server/…` and bare `"vec0"`. A fresh clone boots with zero environment variables.

### Dependencies

- Removed `lazy_static` and `once_cell`. Migrated to `std::sync::{LazyLock, OnceLock}` (stable since Rust 1.80). No behaviour change.
- `[profile.release]` added: `lto = "thin"`, `codegen-units = 1`, `strip = "symbols"`. Longer first builds; smaller, faster binary.
- `rust-version` → `1.100`.
